# react-native-pear-end

**Status:** pre-alpha. Scaffolding only. Real implementation lands when the reference integration's artifact bundle arrives.

A reusable packaging layer that lets a React Native app embed a [Bare](https://github.com/holepunchto/bare) worklet running a full Pear-style backend (corestore + hypercore + hyperswarm + hyperdht + autobase + hyperbee + udx-native), with a typed RPC bridge to the RN UI layer.

## What this is

The runtime story (Bare on Android + iOS via [`react-native-bare-kit`](https://github.com/holepunchto/react-native-bare-kit)) already works — proven end-to-end on real hardware by an existing production integration. What's been missing is a reusable package that hides the friction tax that integration paid to get there: Gradle linking, iOS xcframework staging, build-time bundler invocation, lifecycle wiring, platform-specific gotchas, and the upstream patches needed for 32-bit ARM.

This package wraps all of that so a consumer can:

```sh
npm install react-native-pear-end
cd ios && pod install
```

```kotlin
// android/app/build.gradle
plugins { id 'io.pearend.gradle' version '0.1.0' }
```

```ts
import { PearEnd } from 'react-native-pear-end'

const pear = await PearEnd.start({
  bundle: require('./worklet-bundle'),  // generated by `pear-end pack`
  storage: RNFS.DocumentDirectoryPath,
})

const result = await pear.rpc.call('vault:unlock', { passphrase })
```

— and never touch Gradle bare-link rooting, addon staging, xcframework copying, TextEncoder encoding for `Worklet.start`, dynamic-import workarounds, IPC framing, patch application, or Metro platform shims.

## What this is NOT

- Not a Pear runtime. We depend on [`react-native-bare-kit`](https://github.com/holepunchto/react-native-bare-kit) for that.
- Not an opinionated app framework. Your worklet does whatever it wants.
- Not HiveRelay-specific. The package doesn't import any relay-client code. Apps using this can talk to any swarm or no swarm at all.
- Not a replacement for [`bare-native`](https://github.com/holepunchto/bare-native), which targets native-only (non-RN) apps with a different problem space.

## Status

Working title `react-native-pear-end`, currently published under no namespace pending feedback. Initially maintained by the HiveRelay team but built explicitly as a community Pear-mobile SDK — we expect to propose donation to Holepunch once the package has matured and has 2+ real-world adopters, since 95% of what it does is smoothing the developer experience of Holepunch's own stack.

If you're working on Bare-on-mobile and have opinions about the API surface, naming, or scope: open an issue. We'd rather hear feedback now than after a 1.0.

## Scope (planned layers)

1. **Gradle plugin** — runs `bare-link` rooted at the consumer's `node_modules` (not bare-kit's host project — the #1 trip-up for monorepo/workspaces setups). Stages native addons across all 4 Android ABIs.

2. **iOS Pods config** — auto-stages required xcframeworks. Currently the largest unsolved piece in the ecosystem; coordinating with Holepunch on the upstream answer.

3. **`pear-end pack` CLI** — wraps `bare-pack --linked` with per-platform output paths and Metro shim generation.

4. **JS runtime wrapper** — `PearEnd` class hiding the TextEncoder-on-Android gotcha, dynamic-import limitations, AppState lifecycle wiring, and providing typed RPC over BareKit.IPC.

5. **Vendored patches** — `fs-native-extensions` (EINVAL on 32-bit ARM kernel ≥5.10) and `device-file` (inode/mtime check fails on Android reinstall). Both will be upstreamed; the patches are stopgap.

6. **Mobile memory defaults** — `ARGON2_MEMLIMIT_MOBILE = 64 MB` and similar constants exported with docs explaining the cross-device-determinism constraint.

See [`ARCHITECTURE.md`](./ARCHITECTURE.md) for the deeper structure and [`TROUBLESHOOTING.md`](./TROUBLESHOOTING.md) for the empirical learnings the SDK encodes.
